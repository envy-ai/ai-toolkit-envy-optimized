This opt-in custom-node package lets Comfy run independent Hunyuan Instruct int8
workflows from an immutable ai-toolkit CPU arena. It returns standard `MODEL`
objects using installed Pedro definitions and Comfy kernels. It does not call
ai-toolkit to generate images. No Comfy/Pedro source files are patched.

Implementation is experimental and **runtime_qualified is false**. Initial disk
implementation left running services untouched; the user subsequently authorized
deployment, job cancellation/resumption and runtime qualification. The local mod
is now installed for that controlled test. See the validation report for current
evidence and pending gates. Adoption on other active jobs requires coordination
with their owner.

During a later authorized idle window, install `packages/aitk_shared_models` into
both Python environments, then copy this entire directory under Comfy's
`custom_nodes/ComfyUI-AITK-SharedModels`. Install exactly one supported Pedro
`ComfyUI-HunyuanImage3` pack. Start the broker first, and launch a new Comfy process
with:

```sh
export AITK_SHARED_MODELS_ENABLED=1
export AITK_SHARED_MODELS_DEVICE_UUID=GPU-REPLACE_WITH_LOCAL_TORCH_UUID
export AITK_SHARED_MODELS_SOCKET="$XDG_RUNTIME_DIR/aitk-shared-models/broker.sock"
```

The UUID must identify the same physical device as
`str(torch.cuda.get_device_properties(selected_device).uuid)` in both runtimes.
The NVML `GPU-` prefix and letter case are normalized to one validated bare UUID
throughout configuration, capability checks and lease keys. Source hashes in `compatibility.py` pin the inspected Comfy
`30c8766b` / Pedro `84ad3a3` APIs including their current local modifications.
Changed sources require review and requalification; the loader never falls back
to disk loading, conversion, private full-weight pinning or multi-GPU cloning.

Available nodes:

- `AITKSharedHunyuanImage3Loader`: attach a READY store by identity/socket.
- `AITKSharedLoRASnapshot`: clone standard MODEL patch state with a private LoRA
  generation. `latest` is resolved once per execution, included in cache identity
  and pinned through prompt cleanup. Strength zero leaves the base path unchanged.
- `AITKSharedModelStatus`: CPU-only JSON broker/store/client/owner/snapshot status.

Use `workflows/hunyuan_instruct_shared_edit.json` as an API prompt template. Replace
store identity, snapshot generation, VAE/vision names and reference image. It reuses
Pedro image conditioning and standard sampler/decode/save nodes. Text-only previews
are generated by the trainer provider by replacing the image encoder and removing
reference/vision loaders. The initial sampling contract is Euler/simple, with the
encoder-generated unconditional branch rather than a separate negative prompt.

When enabled, **all Comfy prompts** are gated before any nodes execute, including
cached-loader prompts and workflows without shared nodes. The extension installs
one narrowly source/signature-checked, reversible `PromptExecutor.execute_async`
wrapper. It acquires in the execution worker, holds through VAE/vision/sampler/decode,
and releases only after stream synchronization, global model unload, shared-master
restore, staging/cast-buffer cleanup and zero surviving CUDA allocator bytes. Failed
cleanup retains exclusive ownership. Waiting remains cancellable; cancelling an
inflight broker request drains its response before deciding whether cleanup is needed.

Package-owned non-dynamic ops/patcher bypass AIMDO host packing and private pinning.
Bank-resident Comfy inference kernels remain; dynamic lookahead is disabled.
Throughput against ordinary Comfy is unmeasured and may be materially slower.
Bounded GPU LoRA temporaries are limited to 512 MiB per projection; shared CPU bases
are never merged. Small vision-aligner CPU casts have an explicit 64 MiB bound.

See [the validation report](../../docs/comfy_shared_model_memory_validation.md) for completed CPU evidence and
the remaining two-environment GPU, physical-memory and full-model acceptance gates.
