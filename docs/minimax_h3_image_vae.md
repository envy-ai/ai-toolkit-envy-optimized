# MiniMax-H3-Image VAE

`MiniMaxH3ImageVAE` reuses the native H3 causal encoder, pixel normalization, latent statistics, and spatial tiling. Its image decoder uses the official 24 transformer layers, 16 attention heads of width 64, two-dimensional rotary coordinates over half of each head, a 2D post-quant convolution, and one decoded frame per latent frame. The video VAE retains its existing 36-layer, 32-head, 3D rotary decoder and temporal chunking.

Load the Comfy-format image VAE through `MiniMaxH3ImageVAE.load_model(path)`. Loading is strict; only `latents_mean` and `latents_std` may be absent because the official image config provides their defaults. The model is initialized on the meta device before checkpoint assignment to avoid an extra multi-gigabyte copy. Weights retain their stored precision, including the published FP16 repack. The decoder computes the token embedder, output projection, and normalization in FP32, with optional FP16 autocast elsewhere on CUDA. Existing spatial tiling and ordinary CPU offload remain available.

`encode(pixels, sample=True, generator=None)` accepts `[B, 3, 1, H, W]` pixels in `[-1, 1]` and returns normalized `[B, 24, 1, H/16, W/16]` latents. It samples the posterior with the trainer RNG by default; `sample=False` returns the posterior mean. `encode_reference(pixels)` reproduces the official fixed CPU posterior seed, 42. Latent caches should distinguish those modes and the seed in their cache identity. `decode(latents)` requires one latent frame and returns `[B, 3, 1, H, W]` pixels in `[-1, 1]`.

Architecture and seed follow the [ComfyUI MiniMax image VAE source](https://github.com/Comfy-Org/ComfyUI/blob/ede4e5fe8d15445c6fcd6828d70b202c22f9502c/comfy/ldm/minimax/vae.py) and the official [image VAE configuration](https://huggingface.co/MiniMaxAI/MiniMax-H3-Image/blob/main/vae/config.json). The local reference commit `da58e396690810bed36afa9e4861e910569731a7` is a cherry-pick of that upstream image-support change.
